## 一、现象

```
POST /api/v1/user/register {"username":"test_weak","password":"123"}
→ HTTP 200 / status_code=0  注册成功并建号
```

3 位纯数字密码通过。

## 二、复现步骤

```bash
curl -s -X POST .../user/register -H "Content-Type: application/json" \
  -d '{"username":"test_weak","password":"123"}'
# 改前：200 建号成功
```

## 三、根因

原仓库有长度校验，我们复刻时漏了：

| 原仓库文件:行 | 规则 |
|---|---|
| `create-user.dto.ts:32` | `@MinLength(6)` 「密码长度不能小于6个字符」← 注册 |
| `change-password.dto.ts:25` | `@MinLength(8)` ← 改密码 |

我们的实现：

```go
// auth_service.go:127（改前）
if in.Username == "" || in.Password == "" {   // 只判空
    return nil, errcode.ErrInvalidParam
}
```

`ChangePassword` / `ResetPassword` 同样只有空判。
全仓 `grep "len(.*password) < "` 零命中 —— **没有任何长度校验**。

## 四、修复方案

三处各加校验，**按 rune 计数不是 byte**：

```go
// Register
if utf8.RuneCountInString(in.Password) < 6 {
    return nil, errcode.ErrInvalidParam.WithKey(i18n.AuthPasswordTooShort)
}
// ChangePassword / ResetPassword
if utf8.RuneCountInString(newPwd) < 8 {
    return errcode.ErrInvalidParam.WithKey(i18n.AuthNewPasswordTooShort)
}
```

**为什么按 rune**：中文密码 2 个字 = 6 byte。用 `len()` 会把 2 个汉字误判为「够 6 位」。

**为什么拆两个 i18n key**：注册要 6 位、改密要 8 位，阈值不同。
合并成一个只能写「密码不符合要求」，用户看完还是不知道该敲几位。

## 五、验证

```
3 位密码 → 400/10008 "Password must be at least 6 characters"
4 字中文「密码六位」（12 byte）→ 拒    ┐
5 字中文（15 byte）→ 拒               ├ rune 计数验证通过（byte 判会误放行）
6 字中文 → 通过                        │
6 位英文 → 通过                      ┘
改密 7 位 → 400 "New password must be at least 8 characters"
改密 8 位 → 200 通过

go build OK / go vet 零输出 / go test 16 包全绿
```

## 六、影响与风险

**Breaking change**：存量 6 位以下密码的账号，改密时会被拒（需先设一个 8 位新密码）。
注册侧无存量影响（旧弱密码账号仍可登录）。

**同类未修**：无（三处入口都覆盖了）。

**复发预防**：密码策略应集中在单一函数（如 `validatePassword(pwd, minLen)`），
而不是散在三处各写一遍 —— 这次改动就是三处各加一段，容易漏第四个入口。
