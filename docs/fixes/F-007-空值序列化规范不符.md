## 一、现象

`POST /api/v1/user/login` 返回的 `user` 对象（改前）：

```json
{
  "username": "test_admin",
  "avatar": null,
  "description": null,
  "background": null,
  "address": null,
  "birthDate": null,
  "email": null,
  "phone": null,

}
```

`GET /api/v1/category` 返回（改前）：

```json
{"id":"...","name":"美食","description":"","parentId":"...","link":"","children":null}
```

用户原话：「类似 email、phone、address 这些都应该是字符串或者数组，而不是 null」。

## 三、根因

**三层原因叠加**：

### 3.1 model 层用指针表达「数据库 NULL」，直接透传到了对外 JSON

`internal/model/user.go:53-65`：

```go
Nickname  *string    `json:"nickname"`
Email     *string    `json:"email"`
BirthDate *time.Time `json:"birthDate"`
```

model 用指针是**对的** —— 数据库要区分 SQL NULL 与空串（唯一索引、条件查询都依赖）。
问题在于 `buildUserView` **把指针原样塞进了对外结构**：

```go
// 改前
v := &UserView{ Nickname: u.Nickname, Email: u.Email, BirthDate: u.BirthDate, ... }
```

`json.Marshal` 对 nil 指针输出 `null`。

### 3.2 service 层自己定义了 `UserView`，与 dto 层重复

`UserView` 和 `dto.UserDto` 是两份几乎相同的结构定义。
两处并存 → 改一处忘另一处 → swagger 声明的类型和真实响应漂移。

### 3.3 数组字段用 nil 而不是空切片

`json.Marshal` 的 Go 特性：**nil 切片 → `null`，空切片 → `[]`**。
`buildCategoryTree` 里叶节点从不 append，`Children` 保持 nil → 序列化成 null。

---

## 四、修复方案

### 4.1 定规范（`docs/21-JSON序列化规范.md`）

| 类型 | 空时 | dto 定义 |
|---|---|---|
| 字符串 | `""` | `string` 值类型 |
| 数组 | `[]` | `[]T`，赋值时保证非 nil |
| 对象 / 时间 | **整个字段不传** | `*T` + `omitempty` |

时间为什么是「不传」而不是 `""`：`new Date("")` 得到 `Invalid Date`，比 null 更难排查；
`time.Time` 零值会输出 `0001-01-01T00:00:00Z`，看着像有效数据，最糟。

### 4.2 结构定义统一到 dto（用户要求「使用 dto」）

`internal/service/user_service.go`：

```go
// 改前：service 自己定义一份
type UserView struct { Nickname *string; Email *string; ... }

// 改后：别名到 dto，定义只有一处
type UserView = dto.UserDto
type RoleBrief = dto.RoleBriefDto
```

**为什么用别名而不是改所有签名**：`UserView` 被 7 个文件引用、多个函数签名在用。
别名让调用方零改动，同时把定义权收归 dto —— 两全。

### 4.3 dto 字段改值类型

`internal/dto/user.go` 的 `UserDto`：9 个 `*string` → `string`，
`BirthDate`/`MembershipEndDate` 改 `*string + omitempty`，`Roles` 去掉 `omitempty`。

### 4.4 组装层做转换

`internal/service/user_service.go` 的 `buildUserView`：

```go
Nickname: strOrEmpty(u.Nickname),                    // *string → string
BirthDate: timePtrRFC3339(u.BirthDate),              // *time.Time → *string（nil 保持 nil）
CreatedAt: u.CreatedAt.Format(time.RFC3339),
//
v.Roles = make([]RoleBrief, 0, len(u.Roles))         // 非 nil 保证
```

新增两个公共辅助函数（`internal/service/common.go`）：

```go
func strOrEmpty[T ~string](p *T) string   // nil → ""
func sliceOrEmpty[T any](s []T) []T       // nil → []T{}
```

### 4.5 数据库模型不外泄

`GetConfig` 原本直接返回 `*model.UserProfile` → 表里的 `Remark *string` 变成 `"remark": null`。
改为返回 `*dto.UserConfigDto` + 新增 `userConfigDto()` 转换函数。

**这条是通用原则**：service 层不许把 `*model.Xxx` 直接当对外返回类型。
否则给表加一列就自动泄漏到 API，且 NULL 语义直接外泄。

### 4.6 顺带删掉手写 map 拼装

`toMap(v *UserView) map[string]interface{}` 是 30 行手写的字段拷贝。
改用 `dto.UserProfileDto` 后无人使用，已删除。

**手写 map 的两个问题**：
1. swag 解析不了（swagger 里 `data` 只能是空 `{}`）
2. 加字段容易漏（`toMap` 就漏过 `certification` 之外的所有新增字段）

## 六、影响与风险

### 6.1 Breaking change（前端需同步）

| 字段 | 改前 | 改后 |
|---|---|---|
| `user.avatar` 等 9 个字符串 | `null` | `""` |
| `user.birthDate` / `membershipEndDate` | `null` | **字段不存在** |
| `category.children` | `null` | `[]` |
| `user.roles` | `null`（无角色时） | `[]` |

**前端适配**：把 `=== null` 判断改成 falsy 判断（`""`、`[]`、`undefined` 都是 falsy）：

```js
// 改前
if (user.email === null) { /* 未绑定 */ }
if (user.birthDate !== null) { render(user.birthDate) }

// 改后（falsy 判断，兼容三种空值形态）
if (!user.email) { /* 未绑定 */ }
if (user.birthDate) { render(user.birthDate) }
```

### 6.2 无数据需回补

这是纯序列化层改动，数据库不变。

### 6.3 复发预防

- `docs/21` 规范 + AGENTS 指针
- 两个回归测试（`TestViewUserNoNullFields` / `TestUserProfileCertificationOmitempty`）
- 自查清单里有「扫描 null」的命令

### 6.4 未修（同类问题）

`/upload/config` 的 `data.storage.s3` 仍是 `null`（对象空时应整个字段不传）。
属 upload 域，待该域迁移 DTO 时一并处理。已记 `todo.md`。
