### 1.2 启动与全局链（main.ts / app.module.ts）

- 全局路由前缀：`api/v1`；CORS 全开（`enableCors()` 无配置）。
- `trust proxy` 开启（取真实 IP）。
- helmet（禁用 HSTS，由反代处理）+ compression（gzip）。
- 全局 ValidationPipe（`src/config/validation.config.ts`）。
- 全局拦截器：`TransformInterceptor`（把返回包装成 `{code:200, message:"操作成功", data}`）→ `LoggingInterceptor`（请求日志）。
- 全局异常过滤器：`HttpExceptionFilter`，统一结构 `{code, message, data:null, timestamp, path}`；业务异常优先用异常自带 `code`；校验错误数组只取第一条。
- 全局 Guard（APP_GUARD，按注册顺序）：`JwtAuthGuard` → `ImageDomainGuard`。
- 静态资源：`/uploads/`（multer 目录，图片带 Cache-Control：默认 max-age=2592000 + immutable，视频带宽松 CORS 支持 Range 播放，`Cross-Origin-Resource-Policy: cross-origin`）；`/public/`。
- 优雅关闭：`enableShutdownHooks()`。
- OAuth 第三方登录：GitHub（oauth/github 路由）。
- 启动时 `ConfigUtil.checkAllConfig` 做配置自检；非生产环境做缓存自检（写测试键等 TTL）。

## 2. 鉴权与权限模型

### 2.1 JWT 与 Guard（证据：`src/common/guards/jwt-auth.guard.ts`）

- passport 的 `AuthGuard("jwt")`，secret 来自 `JWT_SECRET`，过期 `JWT_EXPIRES_IN`。
- `@NoAuth()` 装饰器（metadata key `no-auth`）标记公开接口：JWT 验证失败也放行，`request.user` 为 null；验证成功仍解析用户（「可选登录」语义）。
- 全局注册为 APP_GUARD，所有路由默认需要 JWT，除非标 `@NoAuth()`。

### 2.2 RBAC（证据：`src/common/guards/permission.guard.ts`、role/permission entity）

- 关系：`user M:N role M:N permission`（role.permissions 为 eager 加载）。
- `@Permissions("article:create")` 装饰器声明所需权限点；**多个权限是 OR 关系**（`requiredPermissions.some(...)`）。
- Guard 内不查库，直接用 JWT 解析出的 `user.roles[].permissions[].name` 比对。
- 未声明 `@Permissions` 的接口只要登录即可。
- 角色：name 唯一、isEnabled、isSystem（系统角色不可删，需确认删除逻辑细节）。
- 权限点命名风格：`模块:动作`，如 `article:create / article:update / article:delete / banner:create / order:manage / points:manage / audit:read / audit:update / setting:read / user:manage / statistics:read / system:monitor / message:manage / upload:create / upload:list / upload:manage / decoration:manage / report:manage / role:create / achievement:manage / comment:create|update|delete|manage / tag:create|update|delete / category:create|update|delete`。

### 2.3 ImageDomainGuard（图片域名白名单）

- 全局 Guard，仅对 POST/PUT/PATCH 生效；检查 body 中 `background / avatar / cover / images` 四个字段的图片 URL。
- 白名单来自 DB 配置 `image_allowed_domains`（逗号分隔，支持 `*.example.com` 泛域名）；为空不限制；与请求 host 同域自动放行；不合规：单值字段直接删除，数组字段过滤。

### 6.4 invite（邀请分成）

- POST invite（生成邀请码，默认佣金率 0.05）、POST invite/use（绑定邀请人）、GET invite/my、stats、earnings、:id。
- 下单支付成功后按 orderAmount × commissionRate 记 invite-commission，状态 PENDING→PAID；收益统计只累计 PAID，支持按月（DATE_FORMAT 当月）汇总。

### 6.5 order / payment

- 订单类型：文章购买（createArticleOrder，校验文章价格）、会员购买（createMembershipOrder，plan+duration）、余额/佣金订单（createOrderWithCommission）。
- 订单状态机：PENDING → PAID / CANCELLED（cancelOrder，待付才可取消）/ REFUNDED（refund：余额支付原路退余额 + paymentMethod=BALANCE；第三方支付走原路退款申请，两种 refundMethod 均落 payment 记录）。退款用事务（createQueryRunner）。
- 支付：POST payment/create（按订单生成支付参数，渠道由 config 表 `paymentConfig` 决定：alipayEnabled/wechatEnabled/epayEnabled + 对应 appId/privateKey/gateway/notifyUrl，**密钥存 DB 而非环境变量**）。
- 回调（均 NoAuth）：POST payment/notify/alipay（alipay-sdk 验签）、notify/wechat（wechatpay-node-v3）、notify/epay（易支付 MD5 验签：排序拼串排除 sign/sign_type）。回调成功后更新 order→PAID、payment→SUCCESS，触发佣金（CommissionService.handleOrderPayment → 会员权益 + 邀请分成）。
- 查询：GET payment/record/:id、payment/order/:orderId、payment/user。

### 6.10 upload

- GET upload/config（NoAuth，返回上传限制：mime 白名单、大小、数量）。
- POST upload/file（multer 本地或 S3）、upload/avatar（头像，走 image-audit）。
- S3 直传：POST upload/presign（预签名 URL）→ 客户端 PUT → POST upload/confirm（确认入库）。S3 兼容自定义 endpoint（AWS_ENDPOINT/FORCE_PATH_STYLE，可接 MinIO/OSS S3 兼容层）+ CDN 域名（AWS_CDN_DOMAIN）。
- 上传记录列表/管理、迁移工具（migration/stats、process、metadata：本地→S3 迁移）。
- 视频上传进 video-compression 队列（FFMPEG_PATH/FFPROBE_PATH、VIDEO_COMPRESSION_TIMEOUT_MS）。

### 6.11 content-audit（证据：content-audit.controller.ts、providers/）

- GET config / POST config/reload（audit:read/update）：审核提供方与场景开关存 DB 配置（`content_audit_provider` = none/aliyun/tencent，场景 comment/article/image/avatar 独立开关）。
- GET pending-articles：待人工复审文章列表；POST articles/:id/review：人工通过/驳回（改 article.status）。
- POST text、POST image：主动送审（audit:read）。
- 队列：评论/表情上传自动入 Bull 队列异步审核，失败重试 5 次。

### 6.12 search / statistics / banner / report / config / tag / category / collection / role / permission

- search：POST search/sync/articles（全量同步 ES，article:manage）、GET search/status（索引统计）、POST search/clear/articles。ES 索引 mapping 见 `article-search.mapping.ts`，分词器按配置可选 ik_max_word（需 ES 装 ik 插件）否则 standard。
- statistics：GET overview、trends（statistics:read 或 system:monitor，OR 关系）。
- banner：banners CRUD（banner:create/list/update/delete），GET banners/active 公开。
- report：POST report（登录）、GET 列表/统计/详情、PATCH 处理、DELETE（report:manage）。
- config：系统配置 KV 按分组 CRUD（setting:*），GET config/public、config/advertisement 公开；敏感词 CRUD + batch + clear-cache（setting:*）。
- tag/category：标准 CRUD + tag 推荐/关注（follow）；collection：合集 CRUD + 合集内文章增删查 + check/:articleId。
- role：CRUD + :id/permissions（绑定权限）、:id/status、:id/copy（复制角色）。permission：标准 CRUD。

## 9. Go 迁移风险 Top 3

1. **支付回调与订单/佣金事务链**：三种渠道（支付宝/微信/易支付）验签逻辑各异（epay 是自实现 MD5 排序验签），回调成功后要在一个事务里完成 order→PAID、payment→SUCCESS、会员开通、邀请分成入账、事件广播；退款还有余额退款与原路退款两条分支（order.service.ts:650 使用事务）。Go 侧需精确复刻验签细节与幂等（重复回调去重逻辑需确认）。
2. **审核异步管线**：Bull 队列（3 个队列、重试/退避/stalled 语义）+ 双审核提供方（阿里/腾讯）+ 场景开关 + 人工复审状态机（article.status PENDING/REJECTED）。Go 需选型等价队列（asynq/machinery）并复刻「审核失败不阻塞发布但回写状态」的行为。
3. **WebSocket 私信体系**：`/ws-message` 一个 namespace 约 30 个事件、多端在线 presence、已读回执、撤回、拉黑、未读数——语义密集且前端强耦合，迁移期间事件名与 payload 必须逐字节兼容，建议对照 swagger.json 与 test-websocket-client.js 做兼容测试。

次级风险：ImageDomainGuard 全局改写请求体行为、可选登录（@NoAuth 也解析用户）语义、ES ik 分词依赖、运行时 DB 配置（密钥不进 env）。
