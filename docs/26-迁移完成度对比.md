# Go 版 vs 原 NestJS 版 —— 迁移完成度对比

> **系统性对比两边的接口、字段、实体、能力**，找出还没迁移的地方。
>
> 对比时间：2026-11-27
> 原版：`tmp/picart/src`（25 controller / 52 service / 48 entity / 29 module）+ `tmp/picart/swagger.json`（275 操作）
> Go 版：`internal/`（31 handler / 73 service / 26 model / 320 路由）

---

## 一、结论先行

| 维度 | 原版 | Go 版 | 状态 |
|---|---|---|---|
| **HTTP 接口** | 275 | 320 | ✅ **274/275 已迁移**（差 `GET /` hello），另新增 46 个 |
| **响应字段** | 165 个字段名 | 530 个 | ✅ 152 个共有；13 个原版独有（**全部有合理解释，见 §三**） |
| **数据实体** | 48 | 26 个文件（含多表） | ⚠️ **2 个真缺失**：`downloads`、`level_transactions` |
| **功能能力** | 45 个 service | 73 个 | ✅ 抽查 9 个关键能力全部有真实现 |

**总判断：功能面基本迁移完成，剩 2 个数据实体缺口（见 §四）。**

## 二、接口层：274/275 已迁移

```
原 NestJS 接口: 275
Go 版接口:      320
两边都有:       274
❌ 只在原版:      1   ← GET /（AppController.getHello，返回 "Hello World" 示例）
✅ 只在 Go:      46   ← 新增的（认证增强、绑定管理、上传迁移、预约等）
```

### `GET /` 不迁的理由

```typescript
@Get()
@NoAuth()
getHello(): string {
  return this.appService.getHello();   // 返回 "Hello World!"
}
```

这是 NestJS CLI 脚手架自带示例，无业务语义。Go 版用 `/health` 取代（返回依赖状态、WS、队列等真实可观测信息）。

## 三、13 个「原版独有」字段：全部有解释

| 字段 | 所属原版 schema | 判断 |
|---|---|---|
| `trade_no` `out_trade_no` `trade_status` `total_amount` `buyer_id` | `AlipayNotifyDto` | ✅ **不需要**：支付宝回调，我们收原始 `*http.Request` 由 SDK 验签解析，不声明 DTO |
| `transaction_id` `out_trade_no` `trade_state` `openid` | `WechatNotifyDto` | ✅ 同上 |
| `verification_code` | `CreateUserDto` / `UpdateUserContactDto` | ⚠️ **待确认**：管理端创建用户 / 改联系方式时是否需要独立验证码字段 |
| `ban_reason` `membership_start_date` | `UpdateUserDto` | ⚠️ **缺失**：管理端封禁原因、会员开始日期 |
| `extraction_code` `visible_without_permission` | `DownloadDto` | ❌ **真缺失**（见 §四 缺口 1） |

**支付回调那 9 个是正确的不声明** —— 上游 POST 的是表单/XML，我们用 SDK 解析原始 request，
声明 DTO 反而会误导前端以为要按这个结构发。

**`ban_reason` / `membership_start_date` 值得补**（管理端会用）：

```go
// dto.UpdateUserRequest 建议新增
BanReason           string `json:"ban_reason" example:"违规发布"`
MembershipStartDate string `json:"membership_start_date" format:"date-time"`
```

## 四、2 个真缺口

### 缺口 1：`downloads` 表 —— 声明了 DTO 但从未实现

**现状**：

```go
// internal/dto/article.go — ArticleDownloadRequest 存在
type ArticleDownloadRequest struct {
    Name string `json:"name"`
    URL  string `json:"url"`
    Size string `json:"size"`
    Type string `json:"type"`
    Code string `json:"code"`
    Note string `json:"note"`
}

// ArticleDto / ServiceArticleDto 都声明了
Downloads []ArticleDownloadRequest `json:"downloads"`
```

**但**：
- `internal/model/` 里**没有 Download 表**
- `grep "\.Downloads\s*=" internal/` → **零赋值**
- 所以这个字段**永远返回 `null`**

**原版结构**（`download.entity.ts` + `download.dto.ts`）：

```typescript
@Entity()
export class Download {
  id: number;
  articleId: number;
  type: DownloadType;        // baidu/onedrive/google/quark/aliyun/dropbox/direct/lanzou/mega/other
  url: string;
  password?: string;
  extractionCode?: string;
  visibleWithoutPermission?: boolean;
  // 关联 article（@ManyToOne）
}
```

**原版是独立表 + `@OneToMany`**，不是 jsonb 字段。且有 10 个 `DownloadType` 枚举值。

**我们的字段名也不同**（`name/size/code/note` vs `type/url/password/extractionCode/visibleWithoutPermission`）。

**影响**：文章详情里「下载资源」区块是空的。前端如果依赖这个字段，拿到的是 `null`。

**修法**：
1. 建 `model.Download`（表 `downloads`，含 `article_id` 外键 + 6 业务字段）
2. `ArticleDownloadRequest` 改名为 `DownloadDto` 并对齐原版字段
3. `CreateArticleRequest` / `UpdateArticleRequest` 接受 `downloads` 数组，service 层事务内同步
4. `ArticleDto.Downloads` 从关联表读取（列表页可 `Preload` 或批量查）

**成本**：约 200 行（model + service 同步逻辑 + 迁移 + 测试）。

### 缺口 2：`level_transactions` 表 —— 经验值没有流水

**现状**：

```go
// internal/service/level.go:49
func (s *UserService) AddExperience(ctx, in AddExperienceInput) (oldLevel, newLevel int, leveledUp bool, e *errcode.Err)
```

只做 `user.experience += amount`，**没有流水记录**。

**原版**（`level-transaction.entity.ts`）：
```typescript
@Entity({ comment: "等级经验交易记录表" })
export class LevelTransaction {
  id: number;
  userId: number;
  amount: number;      // 正数获得、负数扣除
  // + 来源、时间、关联 ID
}
```

**影响**：
- 用户看不到「经验值明细」（积分有流水，经验没有）
- 出问题时无法追溯经验值怎么来的
- 对账困难

**注意**：原版**也没有对外接口**暴露这个表（`/level` 相关路径零命中），所以是**内部审计表**。

**修法**：
1. 建 `model.LevelTransaction`（表 `level_transactions`）
2. `AddExperience` 在同一事务里写一条流水
3. 可选：加 `GET /user/level/transactions` 对外暴露（原版没有，属增强）

**成本**：约 80 行。**优先级低于缺口 1**（不影响对外功能，只影响可审计性）。

## 九、自查命令

```bash
# ① 接口级对比
python - <<'PY'
import json, re
o = json.load(open('tmp/picart/swagger.json', encoding='utf-8'))['paths']
g = json.load(open('docs/swagger/swagger.json', encoding='utf-8'))['paths']
norm = lambda p: '/' + re.sub(r'\{[^}]+\}', '{X}', p.strip('/'))
os_ = {(norm(p),m.upper()) for p,i in o.items() for m in i if m in ('get','post','put','patch','delete')}
gs_ = {(norm(p),m.upper()) for p,i in g.items() for m in i if m in ('get','post','put','patch','delete')}
print('只在原版:', sorted(os_-gs_))
PY

# ② 字段级对比
python - <<'PY'
import json, re
def defs(d): return d.get('components',{}).get('schemas') or d.get('definitions') or {}
def snake(n):
    s1 = re.sub(r'([A-Z]+)([A-Z][a-z])', r'\1_\2', n)
    return re.sub(r'([a-z0-9])([A-Z])', r'\1_\2', s1).lower()
o = defs(json.load(open('tmp/picart/swagger.json', encoding='utf-8')))
g = defs(json.load(open('docs/swagger/swagger.json', encoding='utf-8')))
oa = {snake(p) for s in o.values() for p in (s.get('properties') or {})}
ga = {p for s in g.values() for p in (s.get('properties') or {})}
print('只在原版:', sorted(oa-ga))
PY
```
