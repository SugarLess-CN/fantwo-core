## 一、概念对齐：三个容易混的东西

| 词 | 在本项目里指什么 | 对应代码 |
|---|---|---|
| **媒体库** | `uploads` 表 —— 所有上传文件的元数据登记册，**不存文件内容** | `model.Upload` |
| **存储桶（bucket）** | S3/MinIO 里的 bucket；本地驱动时退化为一个目录 | `S3Config.Bucket` / `StorageConfig.LocalDir` |
| **存储驱动** | `local`（本地磁盘）或 `s3`（S3 兼容对象存储） | `StorageConfig.Driver` |

**关键认知**：媒体库是**逻辑层**（数据库记录），存储桶是**物理层**（文件在哪）。
两者通过 `Upload.Storage` + `Upload.Path` 关联。**同一个文件可能只存物理一份，但被多条业务记录引用**（见 §六 引用计数）。

## 二、存储驱动：两选一，启动期决定

### 2.1 配置项（`internal/config/infra.go`）

```go
type StorageConfig struct {
    Driver   string // local（默认）| s3
    LocalDir string // 默认 ./uploads
}

type S3Config struct {
    Endpoint       string  // MinIO / AWS S3 / 阿里云 OSS 的 S3 兼容端点
    Bucket         string
    Region         string
    AccessKey      string
    SecretKey      string
    UseSSL         bool
    ForcePathStyle bool
}

type CDNConfig struct {
    BaseURL string // 返回给前端的 URL 前缀；空则按驱动回退
}
```

### 2.2 驱动选择逻辑（`infra.go:196-202`）

```
driver = lower(trim(config.storage.driver))
if driver != "s3"          → driver = "local"
if driver == "s3" && (bucket=="" || endpoint=="")  → driver = "local"  ← 静默降级
```

**两个要点**：
1. **`s3` 配置不全时静默降级成 `local`**，只在启动日志里能看到，运行期无感知。
2. **`storage.driver` 属于「启动期只读」配置** —— minio client 在 `New()` 时初始化，
   改了必须重启。这是 `ConfigStartupOnlyKeys` 白名单里的一项，**不能通过 `/config` 运行期改**。

### 2.3 各驱动行为对比

| 维度 | `local` | `s3` |
|---|---|---|
| 文件落地 | 磁盘 `<LocalDir>/YYYY/MM/DD/HH/<2位>/<sha256>.<ext>` | `PutObject` 到 bucket，key 同上 |
| URL 生成 | 有 CDN → `cdn_base_url/<rel>`；无 CDN → `/uploads/<rel>`（handler 补请求域名） | 有 CDN → `cdn_base_url/<key>`；无 CDN → `endpoint/bucket/<key>` |
| 静态路由 | 注册 `/api/v1/uploads/*`（`v1.Static`） | 不注册 |
| 直传 | **不支持**（`/upload/presign` 返回 503） | 支持预签名 PUT |
| 删除 | `os.Remove` | `RemoveObject` |

## 三、上传的两条路径

### 3.1 路径 A：后端中转（两种驱动都支持）

```
POST /upload/file  (multipart/form-data)
  ↓
HandleUpload(files, metadata, scene, baseURL, userID)
  ↓ 逐个文件 uploadOne()
   ① 校验：checkSize（按 mime 分类限额）+ checkMagic（魔数嗅探，防伪造扩展名）
   ② 算 sha256 → findByHash 查重
      命中 → reference_count +1，**不落盘**，直接返回已有记录
   ③ 落盘/上传（按 driver 分支）
   ④ 落库 uploads 记录
   ⑤ dispatchAsync() → 异步任务
```

**场景（`scene`）**：`avatar` / `image` / `other`。**`avatar` 不加水印**（对齐原仓库 `skipScenes`）。

### 3.2 路径 B：S3 直传（仅 `s3` 驱动）

```
① POST /upload/presign  {filename, contentType, size}
   → {uploadUrl, accessUrl, key, expiresIn: 300}
   （后端只生成预签名，不碰文件内容）

② 前端 PUT 到 uploadUrl（直传 S3，绕过后端）

③ POST /upload/confirm  {key, url, originalName, mimeType, size, hash?, scene?}
   → 后端落库 + verifyS3Magic()（**重新下载头部 64 字节嗅探魔数**）
```

**`verifyS3Magic` 是安全关键**：直传时后端没见过文件内容，必须在确认阶段补一次魔数校验，
否则前端可以声明 `image/png` 实际传 `.exe`。

### 3.3 异步处理链（`dispatchAsync`）

```
上传成功
  ├── 图片（image/*）→ processImageThumbnails()
  │     ├── ensureThumbnails()：按 thumbnailSpecs 生成多档缩略图
  │     ├── 压缩（compressionEnabled 时）
  │     └── 水印（watermarkEnabled 且 scene != avatar）
  └── 视频（video/*）→ enqueueVideoCompression()（asynq 任务）
```

**降级语义**：压缩关 + 水印关 → 整个处理链跳过（对齐原 `upload.service.ts:332-373` 三分支）。

## 四、运行时配置层（DB 优先）

上传相关参数**大部分运行期可调**（走 `ConfigService`，DB 优先、env 兜底）：

| 读取函数 | 对应 DB key | env 兜底 | 默认值 |
|---|---|---|---|
| `uploadLimitMB` | `upload_max_image_mb` / `_video_` / `_audio_` / `_other_` | `UPLOAD_MAX_*_MB` | 20 / 500 / 50 / 100 |
| `uploadMaxFileCount` | `upload_max_count` | `UPLOAD_MAX_COUNT` | 10 |
| `compressionEnabled` | `upload_compression_enabled` | `UPLOAD_COMPRESSION_ENABLED` | true |
| `watermark*` | `upload_watermark_enabled` 等 5 项 | `UPLOAD_WATERMARK_*` | true |
| `localDirRoot` | `storage_local_dir` | `STORAGE_LOCAL_DIR` | `./uploads` |
| `cdnBaseURL` | `cdn_base_url` | `CDN_BASE_URL` | 空 |
| `thumbnailSpecs` | `upload_thumbnail_specs`（JSON 数组） | `UPLOAD_THUMBNAIL_SPECS` | 单档兜底 |

**例外（只读启动期）**：`storage.driver` + `s3_*` 五项。

**优先级**：`默认值 < config.yaml < .env < .env.local < 真实 env < DB`（DB 最高，因为要运行期可调）。
（`s3_*` 例外：DB 种子已删，只有 env）

**缓存语义**：`ConfigService` 是进程级单例，Redis 一级缓存 TTL 10 分钟，**所有写入口带 invalidate**。

## 五、媒体库的数据模型（`uploads` 表）

```go
type Upload struct {
    BaseModel                        // id / created_at / updated_at / deleted_at(soft_delete)
    Hash           string  // sha256，uniqueIndex —— 去重主键
    OriginalName   string
    Storage        string  // "local" | "s3"
    Filename       string
    Path           string  // 物理路径或 S3 key
    URL            string
    Size           int64
    MimeType       string

    ReferenceCount int     // 被多少业务记录引用（去重时的核心）

    OriginalJSON   string  // jsonb：原图信息
    ThumbsJSON     string  // jsonb：缩略图数组
    Processed      bool
    Watermarked    bool

    VideoCompressionStatus string  // pending / processing / done / failed
    VideoJobJSON           string  // jsonb：asynq 任务信息

    Scene          string   // avatar | image | other
    UserID         *string  // 游客上传为 NULL
    AuditStatus    string   // pending / approved / rejected
    AuditResultJS  string   // jsonb
}
```

### 特殊约束（踩过的坑）

1. **`BeforeCreate` 会把空 jsonb 列写成 JSON `null` 字面量** —— PG 的 jsonb 不接受空字符串（22P02）。
2. **`deleted_at` 用 `soft_delete.DeletedAt`** → **未删除 = `0`，不是 NULL**。
   手工造数据写 NULL 会查不出来。
3. **`ThumbsJSON` 里的 `'null'` 是 jsonb 字面量，不是 SQL NULL** ——
   统计"有缩略图"必须用 `thumbnails::text <> 'null'`，用 `IS NOT NULL` 会虚高（T-36 修过这个）。

## 六、引用计数与去重（媒体库的核心机制）

```
同一文件第二次上传
  → findByHash 命中
  → reference_count += 1（UpdateColumn，不走 BeforeUpdate）
  → **不落盘、不新建记录**
  → 返回已有 Upload 记录
```

**目的**：同一张图被多个帖子引用时，磁盘只存一份。

**删除语义**（`RemoveUpload`）：
```
reference_count > 1  →  只 -1，不删文件
reference_count == 1 →  删物理文件 + 软删记录
```

**当前实现的隐患**：`reference_count` 的增减**没有事务保护**，并发上传同一文件可能算错。
（见 `docs/24` 的建议 §R3）

## 七、迁移机制（本地 → S3）

| 端点 | 作用 |
|---|---|
| `GET /upload/migration/stats` | 统计：总数 / 各存储分布 / 带缩略图数 / 待补元数据数 |
| `POST /upload/migration/process` | 批量把 `storage=local` 的文件上传到 S3，改 `storage`/`path`/`url` |
| `POST /upload/migration/metadata` | 回填 `processed` / `thumbnails` 等元数据 |

**权限**：三者都要求 `upload:delete`（**不是** `upload:manage`，这是个不一致点）。

**`dryRun` 参数**：`process` 支持试运行，只统计不实际搬迁。

**已知限制**：
- 迁移**单向**（local → s3），没有回滚
- 迁移中若文件已被删除，跳过并计入 `skipped`
- **没有断点续传**，中断后重跑会重新扫描全部

## 八、路由与鉴权全表

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/upload/config` | **NoAuth** | 上传限制配置（对齐原 `@NoAuth`） |
| GET | `/upload/info/:id` | **NoAuth** | 文件元数据（含 path/hash/userId） |
| GET | `/upload` | 登录（`upload:list` 看全站，否则只看自己） | 列表 |
| POST | `/upload/file` | `upload:create` | 后端中转上传 |
| POST | `/upload/avatar` | `upload:create` | 头像（不加水印） |
| POST | `/upload/presign` | `upload:create` | S3 直传预签名 |
| POST | `/upload/confirm` | `upload:create` | 直传确认入库 |
| DELETE | `/upload/:id` | `upload:delete` | 删除 |
| GET | `/upload/migration/stats` | `upload:delete` | 迁移统计 |
| POST | `/upload/migration/process` | `upload:delete` | 执行迁移 |
| POST | `/upload/migration/metadata` | `upload:delete` | 回填元数据 |

**两个 NoAuth 端点的风险**：知道 upload id 就能读到 `path` / `userId` / `hash` / `originalName`。
原仓库就是公开的（对齐 `@NoAuth`），但**构成信息暴露**（已登记为 P2）。

## 九、已知问题清单（现状，未修）

| # | 问题 | 影响 | 优先级 |
|---|---|---|---|
| 1 | `reference_count` 增减无事务 | 并发上传同一文件可能算错，导致该删没删/不该删删了 | P2 |
| 2 | `s3` 配置不全**静默降级** `local` | 生产环境配错 S3 会偷偷写本地盘，只在启动日志可见 | **P1** |
| 3 | 迁移权限用 `upload:delete` | 语义不符（迁移不是删除），且给了删除权限就能迁库 | P2 |
| 4 | `/upload/info/:id` NoAuth 泄露元数据 | 信息暴露 | P2 |
| 5 | 迁移无断点续传、无回滚 | 大批量中断后要重扫 | P3 |
| 6 | `verifyS3Magic` 只嗅探 64 字节 | 精心构造的文件可绕过（如 polyglot） | P3 |
| 7 | 本地驱动不支持直传 | 大文件必须过后端，占内存/带宽 | 设计取舍 |
| 8 | `storage.driver` 不能运行期切换 | 改了要重启 | 设计取舍（minio client 启动期初始化） |

## 十一、一句话总结现状

> **两个驱动、两条上传路径、一套 DB 优先的运行时配置、一个靠 sha256 + 引用计数的去重媒体库。**
>
> 设计骨架是清楚的，但**错误处理偏静默**（S3 配错降级、引用计数无事务）、
> **权限点选得不精确**（迁移用 delete）、**部分端点过公开**（info 无鉴权）。
> 这些在 `docs/24` 里逐条给了建议。
