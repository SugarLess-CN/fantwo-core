# 总结报告存档（reports）

**本目录专门存档本项目的阶段性总结报告。每完成一次改动（一轮验收通过），就必须新增一份编号报告；不得只在对话里口头汇报。**

- 与 `docs/` 的分工：`docs/` 存**正式交付文档**（功能清单、API 清单、选型、联调报告）；`reports/` 存**过程性总结汇报**（这轮改了什么、功能有什么变化、证据是什么）。两份东西不混放。
- 目录位置：工作区根目录下，与 `docs/` 平级。

## 报告机制（硬规则）

1. **触发条件**：一轮改动 `go build` + `go vet` + `go test` 全绿，并完成真机验收后，立即新增一份报告。
2. **命名**：`<两位序号>-T<任务号>-<主题>.md`，例如 `01-T34a-配置常量与种子.md`。序号只增不改，不复用、不跳号。
3. **必含小节**（缺一节即视为报告未完成）：
   - `## 一、本轮改了什么` —— 逐文件、逐函数、行号区间，写清「改前 → 改后」
   - `## 二、功能变化（对用户/前端/运维可见）` —— 行为差异，含「改前是什么行为、现在是什么行为」
   - `## 三、配置项清单` —— key、类型、默认值、分组、是否公开、是否敏感打码
   - `## 四、验证证据` —— **真实命令与真实输出**，不许写「已验证」「已通过」这类无证据描述
   - `## 五、遗留与风险` —— 没做的、有延迟生效的、有兼容性影响的，逐条列
4. **禁止**：只写「已完成」「已优化」；把计划当结果写；用形容词代替数字和输出。

## 当前任务线：配置迁移到 DB

把 env 里「运行期可调整」的配置迁到 DB `config` 表，让后台可管理、改完**不重启**即生效。

**不迁项（已决策，勿再议）**

| 项 | 原因 |
|---|---|
| `storage.driver` | minio client 在启动期初始化，改了必须重启，不属于「运行期可调」 |
| **S3 七项**（endpoint / bucket / region / access_key / secret_key / use_ssl / force_path_style） | 同上，绑 minio client 生命周期。**不写种子**：库里留一条永不生效的假配置比不迁更危险（运维改了以为生效，实际对象仍写旧桶）。key 常量保留作预留，将来做「签名变化 → 惰性重建 client」时启用 |
| ES 连接池参数（超时、并发数） | 客户端内部状态，无 DB 语义，不进 config 表 |
| `sensitive_words` 明文返回（管理端） | 敏感词管理端点本就要明文，不参与打码；但 `/config/public` 必须剔除 |

**已决策项（用户裁定，2026-11-22）**

| 决策 | 结论 |
|---|---|
| `configCacheTTL`（Redis 配置缓存 10 分钟） | **不收窄**。走后台 API 改配置会立即 invalidate；用 SQL 直改库最多等 10 分钟才生效，接受此代价 |
| `upload_compression_enabled` | **必须真生效**：控制「是否压缩 + 是否生成缩略图」，水印开关独立。对齐原 `upload.service.ts:332-373` 语义，不做纯展示项 |
| 启动期配置 key（S3 七项 + `storage_driver`） | 管理端 `POST /config` / `PATCH` 不得创建或改写，避免手工造出假配置 |
| 新增配置项入库 | 已直接补进 `fantwo_core` 库，42 条与 `DefaultConfigSeeds()` 逐字一致（SQL：`tmp/add_config_seeds.sql`，幂等 `ON CONFLICT (key) DO NOTHING`） |
