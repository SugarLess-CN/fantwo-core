## 二、功能变化（对前端 / 运维 / 用户可见）

### 2.1 对前端

**改前**：只有 GitHub OAuth 3 条端点（旧实现不解析 scope、Redis 故障时 state 校验 fail-open）。
**改后**：

1. 新增 8 个端点（全部挂 `/api/v1`）：

| 端点 | 方法 | 用途 |
|---|---|---|
| `/user/oauth/wechat/web/url` | GET | 微信扫码授权链接（含 `#wechat_redirect`） |
| `/user/oauth/wechat/web/callback` | GET / POST | 微信回调（重定向 / SPA 两模式） |
| `/user/oauth/wechat/app/login` | POST | App 交 code 登录 |
| `/user/oauth/qq/web/url` | GET | QQ 网页授权链接 |
| `/user/oauth/qq/web/callback` | GET / POST | QQ 回调（两模式） |
| `/user/oauth/qq/app/login` | POST | App 交 accessToken+openId 登录（**必须后端校验**） |
| `/user/oauth/github/url`、`/user/oauth/github/callback` | GET / POST | 既有 3 条，路径不变，内部已迁 SDK |

2. 登录成功响应结构与既有 GitHub 登录**逐字一致**：`{user, token, refreshToken, id, isMember}`，前端零改动。
3. 登录行为：同一平台跨渠道（微信 web 扫过码、App 再登）复用同一账号——靠 unionid 优先查找；
   unionid 空（GitHub / QQ 未申请权限）退回 openid 查找；都未命中自动建号（随机密码，不可密码登录）。
4. 错误语义可区分：10008 参数/code 无效（重试无用或重走授权）/ 10002 平台 token 过期（引导重新授权）/
   10003 伪造 token（安全事件）/ 20026 配置缺（运维信号）/ 503 state 存储故障（fail-closed，绝不放行）。

### 2.2 对运维

1. config 表新增 oauth 分组 20 键（管理端可管；4 项凭据打码 `***`）。
2. 未配置降级：任一 (provider, channel) 配置缺齐 → 该组合端点统一 20026，不 500 不放行。
3. 灌库脚本 `tmp/oauth-credentials.sql`（幂等 ON CONFLICT；gitignored）；
   **先启动服务再灌库有 10 分钟进程内缓存时序，灌完重启**（真机踩过，docs/15 §4.1 已写明）。
4. user_oauth_binding 表落库（绑定关系 + 昵称头像快照，不存平台 token）。
