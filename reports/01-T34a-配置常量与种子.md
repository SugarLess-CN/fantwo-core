## 一、本轮改了什么

**唯一改动文件**：`internal/model/config.go`（125 行 → 169 行，+44 行）。未触碰任何其它文件。

### 1.1 新增分组常量（`ConfigGroup*` 块，文件第 27-28 行）

| 常量 | 值 | 用途 |
|---|---|---|
| `ConfigGroupStorage` | `"storage"` | 存储类配置分组（本地目录 + S3 七项） |
| `ConfigGroupCDN` | `"cdn"` | CDN 域名分组 |

改前：分组只有 `system / site / upload / advertisement / payment / audit / search / invite / article` 九个，存储与 CDN 无处安放，只能混进 `system`。改后独立成组，`GET /config/group/storage`、`GET /config/group/cdn` 可直接按组取。

## 二、功能变化（对用户 / 前端 / 运维可见）

| # | 改前 | 改后 |
|---|---|---|
| 1 | 存储目录、S3 七项、CDN 域名、ES 连接参数只能在 `.env` / `config.yaml` 里改，改完必须重启进程 | 这些 key 首次启动自动写入 `config` 表，后台可通过 `PATCH /config` 修改（生效链路由 T-34b/c/d 三个成员接上） |
| 2 | `GET /config/group/storage` 返回 404/空（没有 storage 分组） | 返回 8 条存储配置（改后立即可用） |
| 3 | 老库升级要手工补插配置项 | `EnsureSeeds` 是**幂等**的（`config_service.go:69-101`：先 `Pluck` 既有 key → 已存在则 `continue` → 只 `Create` 缺的），老库重启后自动补齐这 14 条，**无需清表、无需手工 SQL** |
| 4 | `GET /config/public` 不可能含存储/搜索连接参数 | 新种子中仅 `cdn_base_url` 标 `public=true`（前端拼资源地址需要）；S3 七项、`search_*` 连接参数全部 `public=false`，不会从匿名接口泄漏 |
